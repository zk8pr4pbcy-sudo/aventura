# Database

Aventura uses PostgreSQL as the database contract. These migrations are provider-neutral and contain no production credentials.

## Migration order

1. `001_initial_schema.sql`
2. `002_reference_numbers.sql`

## Request references

Internal records use UUID primary keys. Public-facing request references are separate and generated by PostgreSQL:

- Experience: `AV-EXP-YYYY-000001`
- Collaboration: `AV-COL-YYYY-000002`

The sequence is intentionally shared so a public reference is never reused across request types.

## Important integrity boundary

`request_status_history` and `internal_notes` use a polymorphic `request_kind + request_id` pair because they can point to either request table. PostgreSQL cannot express that pair as a conventional foreign key to two target tables. The service layer must validate the target request before inserts, and tests must protect this rule.

No customer data should be inserted until the production database location, retention policy, backups, access controls, and secrets management are approved.
